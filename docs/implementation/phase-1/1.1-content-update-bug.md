## Problem Statement

When `addKnowledge()` is called with an item that has the same fingerprint as an existing item, the content is updated but the **inverted index is not rebuilt**. This causes:

1. **Stale search results** - Old tokens remain in the inverted index
2. **Missing matches** - New tokens in updated content are never indexed
3. **Incorrect BM25 scores** - `docLengths` map still reflects old document length

## Current Code (Buggy)

```typescript
// Lines 350-360 in KnowledgeStore.ts
const existing = this.itemByFingerprint.get(fingerprint);
if (existing) {
    existing.content = item.content;  // Content changes!
    existing.confidence = Math.max(existing.confidence, item.confidence);
    existing.tags = [...new Set([...existing.tags, ...item.tags])];
    existing.keywords = [...new Set([...existing.keywords, ...item.keywords])];
    existing.updated = now;
    this.dirty = true;
    // NOTE: Comment in code acknowledges this:
    // "Note: Should rebuild indices if content changed significantly"
    // "For now, skip as tags/keywords mostly additive"
    return existing;
}
```

## Root Cause Analysis

The code assumes that content updates are "mostly additive" for tags/keywords, but ignores that:

1. **Content field** is fully replaced, not merged
2. **Tokenization** depends on content (`tokenize()` reads title + content + tags + keywords)
3. **Inverted index** uses tokens, so stale tokens from old content persist
4. **docLengths** map is never updated with new token count

## Fix Implementation

### Step 1: Locate the Bug

Find the `addKnowledge()` method in `KnowledgeStore.ts`. Look for:
```typescript

```

### Step 2: Add Index Removal Before Update

Insert `removeFromIndices()` call **before** modifying content:

```typescript
const existing = this.itemByFingerprint.get(fingerprint);
if (existing) {
    // CRITICAL FIX: Remove old tokens from indices BEFORE updating content
    this.removeFromIndices(existing);

    existing.content = item.content;
    existing.confidence = Math.max(existing.confidence, item.confidence);
    existing.tags = [...new Set([...existing.tags, ...item.tags])];
    existing.keywords = [...new Set([...existing.keywords, ...item.keywords])];
    existing.updated = now;

    // CRITICAL FIX: Re-add with new tokens AFTER updating content
    this.addToIndices(existing);

    this.dirty = true;
    return existing;
}
```

### Step 3: Verify removeFromIndices() Handles Re-Addition

Check that `removeFromIndices()` properly clears all index entries:
- `itemById.delete(item.id)` - Will be re-added by `addToIndices()`
- `itemByFingerprint.delete(item.fingerprint)` - Will be re-added
- `docLengths.delete(item.id)` - Will be recalculated
- `invertedIndex` postings removed - Will be re-created
- `termDocFreq` decremented - Will be incremented again

**Potential Issue**: After `removeFromIndices()`, the item's ID is deleted from `itemById`. This is fine because `addToIndices()` will re-add it.

### Step 4: Handle Edge Case - Same Content

Optimize to skip index rebuild if content hasn't actually changed:

```typescript
if (existing) {
    const contentChanged = existing.content !== item.content ||
                          !arraysEqual(existing.tags, item.tags) ||
                          !arraysEqual(existing.keywords, item.keywords);

    if (contentChanged) {
        this.removeFromIndices(existing);
    }

    existing.content = item.content;
    existing.confidence = Math.max(existing.confidence, item.confidence);
    existing.tags = [...new Set([...existing.tags, ...item.tags])];
    existing.keywords = [...new Set([...existing.keywords, ...item.keywords])];
    existing.updated = now;

    if (contentChanged) {
        this.addToIndices(existing);
    }

    this.dirty = true;
    return existing;
}

// Helper function (add at class level):
private arraysEqual(a: string[], b: string[]): boolean {
    if (a.length !== b.length) return false;
    const sorted1 = [...a].sort();
    const sorted2 = [...b].sort();
    return sorted1.every((v, i) => v === sorted2[i]);
}
```

```typescript
describe('addKnowledge content update', () => {
    it('should index new terms when content is updated', async () => {
        const store = new KnowledgeStore(projectRoot, bus);
        await store.load();

        // Add initial item
        const item1 = store.addKnowledge({
            type: 'module_info',
            title: 'Module: uart',
            content: 'Has clock and reset ports',
            tags: [],
            keywords: [],
            scope: { global: true },
            source: { method: 'extracted' },
            confidence: 0.9
        });

        // Search for original term
        let results = store.search({ query: 'clock' });
        expect(results.length).toBe(1);
        expect(results[0].item.id).toBe(item1.id);

        // Update with new content (same fingerprint via same title/type/scope)
        const item2 = store.addKnowledge({
            type: 'module_info',
            title: 'Module: uart',
            content: 'Has enable and valid signals',  // NEW TERMS
            tags: [],
            keywords: [],
            scope: { global: true },
            source: { method: 'extracted' },
            confidence: 0.95
        });

        // Should be same item (updated in place)
        expect(item2.id).toBe(item1.id);

        // Old term should NOT match
        results = store.search({ query: 'clock' });
        expect(results.length).toBe(0);  // FAILS WITHOUT FIX

        // New term SHOULD match
        results = store.search({ query: 'enable' });
        expect(results.length).toBe(1);  // FAILS WITHOUT FIX
        expect(results[0].item.id).toBe(item1.id);
    });
});
```
