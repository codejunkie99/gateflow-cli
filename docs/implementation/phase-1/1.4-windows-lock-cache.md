# Module 1.4: Cache Windows Lock Check Result

## Overview

| Attribute | Value |
|-----------|-------|
| **File** | `src/memory/KnowledgeStore.ts` |
| **Lines** | 1196-1216 |
| **Severity** | LOW (Performance) |
| **Effort** | 20 minutes |
| **Dependencies** | None |

## Problem Statement

The `isLockStale()` method spawns a `tasklist` subprocess on Windows to check if a process is alive. This takes **200-500ms per call**. In the lock acquisition retry loop, this can be called 10-50 times, causing **2-25 seconds of delay**.

## Performance Comparison

| Platform | Method | Latency |
|----------|--------|---------|
| Unix/Linux | `process.kill(pid, 0)` | ~0.001ms |
| Windows | `spawnSync('tasklist')` | ~200-500ms |
| **Difference** | | **100,000x slower** |

## Current Code (Slow)

```typescript
// Lines 1196-1216 in KnowledgeStore.ts
private async isLockStale(): Promise<boolean> {
    try {
        const content = await fs.readFile(this.lockPath, 'utf-8');
        const lock = JSON.parse(content);

        // Time-based check (5 minutes)
        if (Date.now() - lock.time > 5 * 60 * 1000) return true;

        if (process.platform === 'win32') {
            // SLOW: Spawns tasklist subprocess every time
            const { spawnSync } = await import('child_process');
            const result = spawnSync('tasklist', ['/FI', `PID eq ${lock.pid}`, '/NH'], {
                encoding: 'utf-8',
                timeout: 2000
            });
            return !result.stdout.includes(lock.pid.toString());
        } else {
            // Fast: Signal check
            try { process.kill(lock.pid, 0); return false; }
            catch { return true; }
        }
    } catch {
        return true;
    }
}
```

## Lock Acquisition Context

The retry loop in `acquireLock()` calls `isLockStale()` repeatedly:

```typescript
// Simplified acquireLock() loop
while (Date.now() - start < 5000) {  // 5 second timeout
    try {
        await fs.writeFile(lockPath, data, { flag: 'wx' });
        return;  // Success
    } catch (e) {
        if (e.code === 'EEXIST') {
            if (await this.isLockStale()) {  // ← CALLED HERE
                await fs.unlink(lockPath);
                continue;
            }
            await sleep(100);  // Wait 100ms before retry
        }
    }
}
```

**Worst case**: 50 retries × 200ms = 10 seconds of tasklist calls.

## Fix Implementation

### Step 1: Add Cache Field

Add a private field to cache the lock check result:

```typescript
// Add near other private fields (around line 70)
private lockCheckCache?: {
    pid: number;
    isAlive: boolean;
    time: number;
};
```

### Step 2: Modify isLockStale()

```typescript
private async isLockStale(): Promise<boolean> {
    try {
        const content = await fs.readFile(this.lockPath, 'utf-8');
        const lock = JSON.parse(content);

        // Time-based check (5 minutes)
        if (Date.now() - lock.time > 5 * 60 * 1000) {
            return true;
        }

        // ═══════════════════════════════════════════════════════════
        // FIX: Check cache first on Windows
        // ═══════════════════════════════════════════════════════════
        if (process.platform === 'win32') {
            // Check if we have a recent cache for this PID
            if (
                this.lockCheckCache &&
                this.lockCheckCache.pid === lock.pid &&
                Date.now() - this.lockCheckCache.time < 1000  // 1 second cache
            ) {
                return !this.lockCheckCache.isAlive;
            }

            // Cache miss or expired - do the slow check
            const { spawnSync } = await import('child_process');
            const result = spawnSync('tasklist', ['/FI', `PID eq ${lock.pid}`, '/NH'], {
                encoding: 'utf-8',
                timeout: 2000
            });
            const isAlive = result.stdout.includes(lock.pid.toString());

            // Cache the result
            this.lockCheckCache = {
                pid: lock.pid,
                isAlive,
                time: Date.now()
            };

            return !isAlive;
        } else {
            // Unix: Fast signal check, no caching needed
            try {
                process.kill(lock.pid, 0);
                return false;
            } catch {
                return true;
            }
        }
    } catch {
        return true;
    }
}
```

### Step 3: Clear Cache on Lock Release

To prevent stale cache from affecting future operations:

```typescript
// In releaseLock() method
private async releaseLock(): Promise<void> {
    if (!this.lockAcquired) return;

    try {
        await fs.unlink(this.lockPath);
    } catch {
        // Lock file might already be gone
    }

    this.lockAcquired = false;
    this.lockCheckCache = undefined;  // ADD: Clear cache
}
```

## Alternative: Use Windows Management Instrumentation (WMI)

For even faster checks, consider using WMI through PowerShell or direct API. However, this adds complexity:

```typescript
// Alternative: WMI via PowerShell (still slow but potentially more reliable)
const result = spawnSync('powershell', [
    '-Command',
    `Get-Process -Id ${lock.pid} -ErrorAction SilentlyContinue | Select-Object -Property Id`

    timeout: 2000
});
```

**Recommendation**: Stick with the caching approach. It's simpler and sufficient.

## Cache Duration Rationale

**Why 1 second?**

- Process state changes are rare in the retry loop context
- Lock holder either finishes quickly or is truly dead
- 1 second provides 10+ cache hits during typical 100ms retry intervals
- Short enough to detect process termination reasonably fast

**Why not longer?**

- Process could terminate between checks
- Don't want stale "alive" status preventing lock acquisition

## Edge Cases

| Scenario | Behavior |
|----------|----------|
| Process terminates during cache | May delay detection by up to 1 second |
| PID reuse | New PID triggers fresh check (different PID in lock file) |
| Cache cleared between retries | Fresh check on next iteration |
| Time-based staleness (5 min) | Bypasses PID check entirely |

## Platform-Specific Notes

### Windows
- `tasklist` command is available on all Windows versions
- Output format: `node.exe    1234 Console    1    25,000 K`
- We check for PID as substring in output

### Unix/Linux/macOS
- `process.kill(pid, 0)` sends signal 0 (no-op, just checks existence)
- Throws `ESRCH` if process doesn't exist
- Throws `EPERM` if process exists but no permission (still alive)
