## Problem Statement

The `load()` method's catch block catches **ALL errors** silently, including file corruption. This means:

1. **Corrupted files** are silently replaced with empty data
2. **Permission errors** are swallowed
3. **I/O errors** go unreported
4. **User loses all learned knowledge** without any warning

## Error Types That Should Be Distinguished

| Error Code | Type | Correct Response |
|------------|------|------------------|
| `ENOENT` | File not found | ✅ Create empty (first run) |
| `EACCES` | Permission denied | ❌ Throw error, let user fix permissions |
| `EIO` | I/O error | ❌ Throw error, disk issue |
| `SyntaxError` | Corrupt JSON | ⚠️ Backup + warn + create empty |
| `TypeError` | Invalid schema | ⚠️ Migrate or backup + warn |

## Fix Implementation

### Step 1: Locate the load() Method

Find the `load()` method in `KnowledgeStore.ts` (around line 165).

### Step 2: Replace the Catch Block

```typescript
async load(): Promise<KnowledgeIndex> {
    return this.ioMutex.withLock(async () => {
        await fs.mkdir(this.config.knowledgeDir, { recursive: true });

        try {
            const content = await fs.readFile(this.knowledgePath, 'utf-8');
            this.index = this.migrate(JSON.parse(content) as KnowledgeIndex);
            this.pruneStaleItems();
            this.rebuildAllIndices();
            return this.index;
        } catch (error) {
            // ═══════════════════════════════════════════════════════════
            // FIX: Distinguish between error types
            // ═══════════════════════════════════════════════════════════

            const errCode = (error as NodeJS.ErrnoException).code;

            // Case 1: File doesn't exist - this is fine on first run
            if (errCode === 'ENOENT') {
                this.index = this.createDefaultIndex();
                this.clearAllIndices();
                return this.index;
            }

            // Case 2: Permission denied - user needs to fix this
            if (errCode === 'EACCES' || errCode === 'EPERM') {
                console.error(
                    `KnowledgeStore: Permission denied reading ${this.knowledgePath}\n` +
                    `Please check file permissions.`
                );
                throw error;  // Re-throw - can't proceed without access
            }

            // Case 3: I/O error - disk problem
            if (errCode === 'EIO' || errCode === 'EROFS') {
                console.error(
                    `KnowledgeStore: I/O error reading ${this.knowledgePath}\n` +
                    `Please check disk health.`
                );
                throw error;
            }

            // Case 4: JSON parse error or schema error - file is corrupted
            console.warn(
                `KnowledgeStore: File corrupted or invalid at ${this.knowledgePath}\n` +
                `Error: ${error instanceof Error ? error.message : 'Unknown error'}\n` +
                `Creating backup and starting fresh.`
            );

            // Attempt to backup the corrupted file
            try {
                const backupPath = `${this.knowledgePath}.corrupted.${Date.now()}`;
                await fs.rename(this.knowledgePath, backupPath);
                console.warn(`KnowledgeStore: Corrupted file backed up to ${backupPath}`);
            } catch (backupError) {
                // If backup fails, just log and continue
                console.warn(
                    `KnowledgeStore: Could not create backup: ` +
                    `${backupError instanceof Error ? backupError.message : 'Unknown error'}`
                );
            }

            // Start fresh
            this.index = this.createDefaultIndex();
            this.clearAllIndices();
            return this.index;
        }
    });
}
```

## Backup File Format

Corrupted files are renamed to:
```
{original-filename}.corrupted.{timestamp}
```

Example:
```
abc123def456-knowledge.json.corrupted.1704067200000
```

This allows:
1. Multiple corruptions to be preserved (different timestamps)
2. Easy identification of corrupted files
3. Potential manual recovery by user

## User Communication

When corruption is detected, users will see:
1. **Console warning** with file path and error message
2. **Backup location** for potential manual recovery
3. **Event emission** for UI display (optional)

Example console output:

Error: Unexpected token } in JSON at position 15
Creating backup and starting fresh.
KnowledgeStore: Corrupted file backed up to /home/user/.gateflow/abc123-knowledge.json.corrupted.1704067200000

## Related Considerations

### Schema Migration

The `migrate()` method may throw on incompatible schema changes. Consider wrapping:

```typescript
try {
    this.index = this.migrate(JSON.parse(content) as KnowledgeIndex);
} catch (parseOrMigrateError) {
    // Both JSON.parse and migrate errors handled the same way
}
```

### Atomic Writes Already Implemented

The `save()` method already uses atomic writes (write to temp, then rename), so corruption during save is unlikely. However, crashes during the write can still cause partial files.

### Lock File Cleanup

If the knowledge file is corrupted, check if there's a stale lock file that should also be cleaned:

```typescript
// Optional: Clean up lock file too
try {

} catch {
    // Lock file might not exist
}
```

## Edge Cases

| Scenario | Expected Behavior |
|----------|-------------------|
| Empty file | JSON.parse throws, backup + reset |
| Partial JSON (`{"items":`) | JSON.parse throws, backup + reset |
| Valid JSON but wrong schema | migrate throws, backup + reset |
| Binary file content | JSON.parse throws, backup + reset |
| Backup fails (disk full) | Log warning, continue with reset |
