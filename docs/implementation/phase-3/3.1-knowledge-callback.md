# Module 3.1: Add Knowledge Update Callback to WatchManager

## Overview

| Attribute | Value |
|-----------|-------|
| **File** | `src/watch/watcher.ts` |
| **Purpose** | Allow memory updates when files change |
| **Effort** | 30 minutes |
| **Dependencies** | Phase 2 (extractors) |

## Problem Statement

Currently, `WatchManager` triggers re-indexing via `indexer.updateFile()` when files change, but there's no mechanism to update the knowledge store with fresh data. This means:

1. Structural knowledge becomes stale after file edits
2. Module port changes aren't reflected in AI context
3. New dependencies aren't captured

## Current Code

```typescript
// In WatchManager.runAction() around line 267-269
case 'index':
    for (const [filepath, change] of files) {
        await this.indexer.updateFile(filepath, change.type);
        // ← No knowledge update here
    }
    break;
```

## Solution Design

Add an optional callback that fires after index updates, allowing the MemoryService to re-extract knowledge.

```
File Change
    ↓
handleChange() → debounce
    ↓
processChanges()
    ↓
runAction('index')
    ↓
indexer.updateFile()
    ↓
onKnowledgeUpdate(filepath, changeType)  ← NEW CALLBACK
```

## Implementation

### Step 1: Add Callback Type

At the top of `watcher.ts`:

```typescript
/**
 * Callback invoked after index is updated for knowledge store synchronization
 */
export type OnKnowledgeUpdate = (
    filepath: string,
    changeType: 'add' | 'change' | 'unlink'
) => Promise<void>;
```

### Step 2: Add Callback Field and Setter

In the `WatchManager` class:

```typescript
export class WatchManager {
    // ... existing fields ...

    /**
     * Optional callback for knowledge store updates
     * @private
     */
    private onKnowledgeUpdate?: OnKnowledgeUpdate;

    // ... constructor and existing methods ...

    /**
     * Register a callback to be invoked after index updates
     *
     * This allows the MemoryService to re-extract knowledge when
     * files change, keeping the knowledge store in sync with the
     * indexed project state.
     *
     * @param callback - Function called with (filepath, changeType)
     *
     * @example
     * ```typescript
     * watcher.setKnowledgeUpdateCallback(async (filepath, changeType) => {
     *     if (changeType !== 'unlink') {
     *         await memoryService.refreshKnowledgeFor(filepath);
     *     }
     * });
     * ```
     */
    setKnowledgeUpdateCallback(callback: OnKnowledgeUpdate): void {
        this.onKnowledgeUpdate = callback;
    }

    /**
     * Remove the knowledge update callback
     */
    clearKnowledgeUpdateCallback(): void {
        this.onKnowledgeUpdate = undefined;
    }
}
```

### Step 3: Invoke Callback in runAction()

Modify the `case 'index':` block:

```typescript
private async runAction(
    action: WatchAction,
    files: [string, { type: 'add' | 'change' | 'unlink'; time: number }][]
): Promise<void> {
    switch (action) {
        case 'index':
            for (const [filepath, change] of files) {
                // Update index
                await this.indexer.updateFile(filepath, change.type);

                // ═══════════════════════════════════════════════════════════
                // NEW: Trigger knowledge update callback
                // ═══════════════════════════════════════════════════════════
                if (this.onKnowledgeUpdate && change.type !== 'unlink') {
                    try {
                        await this.onKnowledgeUpdate(filepath, change.type);
                    } catch (error) {
                        // Non-fatal - log and continue
                        console.warn(
                            `[WatchManager] Knowledge update callback failed for ${filepath}:`,
                            error instanceof Error ? error.message : error
                        );
                    }
                }
            }
            break;

        case 'lint':
            // ... existing lint logic ...
            break;

        case 'compile':
            // ... existing compile logic ...
            break;
    }
}
```

## Alternative: Event-Based Approach

Instead of a callback, emit an event that MemoryService subscribes to:

```typescript
// In runAction()
case 'index':
    for (const [filepath, change] of files) {
        await this.indexer.updateFile(filepath, change.type);

        // Emit event for knowledge update
        this.bus.emit({
            type: 'index_file_updated',
            filepath,
            changeType: change.type
        });
    }
    break;

// In MemoryService initialization
this.bus.on('index_file_updated', async (event) => {
    if (event.changeType !== 'unlink') {
        await this.refreshKnowledgeFor(event.filepath);
    }
});
```

**Tradeoff**: Event-based is more decoupled but requires MemoryService to subscribe to WatchManager events.

**Recommendation**: Use callback approach for explicit control and simpler debugging.

## Why Skip 'unlink' Events?

When a file is deleted:
1. The module no longer exists
2. Its knowledge items should expire via normal pruning
3. Attempting to re-extract from a deleted file would fail

The knowledge store's time-based pruning (30 days) and score-based pruning will naturally remove obsolete items.

## Testing Strategy

### Unit Test: Callback Invoked

```typescript
describe('WatchManager knowledge callback', () => {
    it('should invoke callback after index update', async () => {
        const callback = jest.fn().mockResolvedValue(undefined);
        const watcher = new WatchManager(
            projectRoot,
            bus,
            indexer,
            verilator
        );

        watcher.setKnowledgeUpdateCallback(callback);

        // Simulate file change
        await watcher['runAction']('index', [
            ['/test/module.sv', { type: 'change', time: Date.now() }]
        ]);

        expect(callback).toHaveBeenCalledWith('/test/module.sv', 'change');
    });
});
```

### Unit Test: Callback Error Doesn't Break Index

```typescript
it('should continue indexing if callback fails', async () => {
    const callback = jest.fn().mockRejectedValue(new Error('Callback failed'));
    const watcher = new WatchManager(projectRoot, bus, indexer, verilator);
    watcher.setKnowledgeUpdateCallback(callback);

    // Should not throw
    await expect(
        watcher['runAction']('index', [
            ['/test/module.sv', { type: 'change', time: Date.now() }]
        ])
    ).resolves.not.toThrow();

    // Indexer should still have been called
    expect(indexer.updateFile).toHaveBeenCalled();
});
```

### Unit Test: No Callback on Unlink

```typescript
it('should not invoke callback on file deletion', async () => {
    const callback = jest.fn();
    const watcher = new WatchManager(projectRoot, bus, indexer, verilator);
    watcher.setKnowledgeUpdateCallback(callback);

    await watcher['runAction']('index', [
        ['/test/module.sv', { type: 'unlink', time: Date.now() }]
    ]);

    expect(callback).not.toHaveBeenCalled();
});
```
