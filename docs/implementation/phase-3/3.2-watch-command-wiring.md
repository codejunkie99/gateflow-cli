## Purpose

Connect the WatchManager's knowledge update callback to the MemoryService so that:
1. Knowledge is refreshed when watched files change
2. The AI always has up-to-date structural information
3. Users see feedback about knowledge updates

```typescript
/**
 * Configure WatchManager to update knowledge store on file changes
 * @private
 */
function setupKnowledgeUpdateCallback(
    ctx: CommandContext,
    watcher: WatchManager
): void {
    // Check if memory service is available
    if (!ctx.memoryService) {
        return;  // No memory service, skip knowledge updates
    }

    const knowledgeStore = getKnowledgeStore();
    if (!knowledgeStore) {
        return;  // No knowledge store, skip
    }

    watcher.setKnowledgeUpdateCallback(async (filepath, changeType) => {
        // Status feedback
        ctx.bus.emit({
            type: 'status',
            phase: 'memory',
            label: `Updating knowledge for ${path.basename(filepath)}`
        });

        try {
            // Get the updated project from indexer
            const project = ctx.indexer.getProject();
            if (!project) {
                return;
            }

            // Extract knowledge from the updated project
            // Note: Full extraction is simple but not optimal for single-file changes
            // Consider optimizing to only update changed modules
            const result = await extractFromIndex(
                project,
                knowledgeStore,
                createExtractionOptions(knowledgeStore.getProjectId(), {
                    maxItemsPerCategory: 100  // Lower limit for incremental updates
                })
            );

            if (result.success) {
                ctx.bus.emit({
                    type: 'tool_result',
                    tool: 'knowledge_update',
                    ok: true,
                    summary: formatExtractionSummary(result)
                });
            }

        } catch (error) {
            // Non-fatal - just log
            console.warn(
                '[watchCommand] Knowledge update failed:',
                error instanceof Error ? error.message : error
            );
        }
    });
}
```

### Step 3: Alternative - Use MemoryService Directly

If `CommandContext` has a `memoryService` property:

```typescript
function setupKnowledgeUpdateCallback(
    ctx: CommandContext,
    watcher: WatchManager
): void {
    if (!ctx.memoryService) {
        return;
    }

    watcher.setKnowledgeUpdateCallback(async (filepath, changeType) => {
        ctx.bus.emit({
            type: 'status',
            phase: 'memory',
            label: `Refreshing knowledge...`
        });

        // Use MemoryService's built-in refresh method
        await ctx.memoryService.refreshFromIndexer(ctx.indexer);
    });
}
```

This requires adding a `refreshFromIndexer()` method to MemoryService:

```typescript
// In MemoryService
async refreshFromIndexer(indexer: SVIndexerAdapter): Promise<void> {
    const project = indexer.getProject();
    if (!project || !this.knowledgeStore) {
        return;
    }

    await extractFromIndex(
        project,
        this.knowledgeStore,
        createExtractionOptions(this.knowledgeStore.getProjectId())
    );
}
```

## Optimization: Incremental Updates

For better performance, only update knowledge related to the changed file:

```typescript
watcher.setKnowledgeUpdateCallback(async (filepath, changeType) => {
    const project = ctx.indexer.getProject();
    if (!project) return;

    // Find modules in the changed file
    const changedModules = project.declarations.filter(
        d => d.location.file === filepath &&
             ['module', 'interface', 'package'].includes(d.kind)
    );

    // Only extract knowledge for those modules
    for (const mod of changedModules) {
        // Update this specific module's knowledge
        await updateModuleKnowledge(mod, knowledgeStore, options);
    }
});
```

**Tradeoff**: More complex but faster for large projects. Start with full extraction, optimize later if needed.

## Event Sequence

After integration:

```
User edits uart_tx.sv (in watched directory)

1. chokidar detects change
   → emit: file_change { path: 'uart_tx.sv', type: 'change' }

2. Debounce (300ms)

3. processChanges() runs
   → emit: status { phase: 'watching', label: 'Processing changes...' }

4. runAction('index') - calls indexer.updateFile()
   → emit: index_update { modified: 1 }

5. Knowledge callback invoked (NEW)
   → emit: status { phase: 'memory', label: 'Updating knowledge for uart_tx.sv' }
   → extractFromIndex() runs
   → emit: tool_result { tool: 'knowledge_update', summary: '...' }

6. runAction('lint') - if configured

7. Complete
   → emit: status { phase: 'watching', label: 'Watching for changes...' }
```
